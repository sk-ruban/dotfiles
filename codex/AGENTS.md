## Planning Communication

- When I ask for a plan, explain the reasoning before asking me to choose.
- Give a recommended path first, then alternatives.
- For each option, explain what it means, the main pros and cons, and when you would choose it.
- Avoid multiple-choice questions unless the decision is truly blocking.
- If clarification is needed, prefer a short natural-language question over a forced choice list.

## Working Style

- Research existing code patterns before making changes.
- For complex tasks, explain the planned approach before implementation and recommend one path first.
- If multiple viable approaches exist, explain the main pros and cons of each.
- Make reasonable assumptions and proceed unless a decision is truly blocking or risky.
- Prefer simple, composable, testable functions over unnecessary abstraction.
- Add comments only when they explain why a decision was made, not what the code does.
- After implementation, run relevant formatters, linters, and tests when available, and report what was validated.
- For bug fixes, add a test that reproduces the issue when practical.
